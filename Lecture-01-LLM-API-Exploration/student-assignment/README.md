# Individual Assignment — LLM API Exploration Report

## Objective

Use the provided FastAPI Swagger interface to conduct a controlled exploration
of an LLM API. Document the request/response structure, compare model behavior,
and identify the boundary between caller-controlled input and generated output.

This is individual work. No FastAPI source-code modification is required.

## Part 1 — API map

Explore `GET /health`, `POST /chat`, and `POST /compare`. For each endpoint,
record:

- Purpose
- HTTP method
- Request fields
- Response fields
- Expected successful status code
- Fields controlled by the caller
- Fields generated by the server or model

## Part 2 — Required experiments

Use this baseline:

```json
{
  "model": "qwen3:4b",
  "messages": [
    {
      "role": "system",
      "content": "Explain concepts to a senior CS student."
    },
    {
      "role": "user",
      "content": "Explain how an LLM generates its next token."
    }
  ],
  "temperature": 0.7
}
```

Conduct these experiments:

1. Baseline request.
2. Change only the user message to require exactly 15 words.
3. Change only the system message to target a nontechnical audience.
4. Run the same request twice at temperature `0.0`.
5. Run it twice at temperature `0.7`.
6. Run it twice at temperature `1.5`.
7. Add one assistant example that demonstrates the headings `Definition`,
   `Analogy`, and `Limitation`, then request the same format.
8. Run the messages through `/compare`.
9. Send one intentionally invalid request, such as temperature `3.0`, and
   document the validation response. This is an API validation test, not an
   attack on an external service.

Change only one variable in each comparison.

## Part 3 — Evidence

Save the request body and response body for every experiment. JSON files are
preferred; clearly readable screenshots are accepted.

For one successful request, annotate:

- Endpoint and HTTP method
- Model
- System, user, and assistant message roles
- Temperature
- Generated response
- Input and output tokens
- Token-usage source
- Latency
- Finish reason
- HTTP status code

For the invalid request, explain:

- Which validation rule was violated
- Whether the request reached the model
- Why API validation and model behavior are separate concepts

## Part 4 — Analysis report

Complete `report-template.md`, and
JSON evidence.

Your analysis must:

1. Explain the path from Swagger to FastAPI to the configured LLM backend.
2. Distinguish the API application from the language model.
3. Explain how message roles become model context.
4. Compare temperature results cautiously.
5. Explain the effect of the few-shot example.
6. Identify caller-controlled and server-generated values.
7. Explain why this data flow matters for later AI-security analysis.
